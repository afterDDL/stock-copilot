# 选股 coPilot Web MVP 设计规格

## 目标与成功标准

构建一个本地可运行的 Next.js Web 产品，让用户从模糊中文选股意图出发，得到可编辑、可追溯、可重复执行的银行股策略和真实股票篮子。成功标准是用户可以完成“自然语言 → 结构化策略 → 冲突修正 → 真实取数 → 确定性筛选/排序 → 入选与排除证据 → 阈值变化 Diff → 两股比较 → 本地保存策略”的完整主链路。

## 范围与边界

- P0 只承诺 A 股银行行业、总市值、2026 年中报归母净利润同比增长率。
- DeepSeek 负责意图理解、局部修改和不支持项识别，不决定股票入选。
- iFinD MCP 负责真实数据。默认实时查询；失败时可使用仓库内带采集时间和数据日期的真实快照，界面必须显示“历史快照”。
- TypeScript 引擎负责白名单、冲突、逐股筛选、缺失分类、排序、Diff 和数值解释。
- 不实现收益预测、任意指标、交易下单、用户账户或生产部署。

## 视觉与交互

视觉完全沿用 ChatGPT 式工作台语言：暖白/浅灰背景、深色正文、低饱和绿色作为主操作色、克制边框与阴影、14–16px 主字号、宽松留白、圆角卡片和自然语言优先。顶部保持轻量品牌栏，页面主体为左侧对话与策略、右侧结果研究区；窄屏改为纵向。避免金融终端式密集行情、闪烁颜色和装饰性按钮。

主交互：

1. 用户输入自然语言，服务端 DeepSeek 返回严格结构化策略。
2. 模糊默认值以“AI 推断”标签呈现，可直接修改；必须澄清时显示真实选项按钮。
3. 条件冲突时阻止执行，每条冲突提供一键修正动作。
4. 首次执行从服务端取得 42 只银行股快照，浏览器调用共享引擎筛选。
5. 用户修改阈值后在同一快照上重新执行，展示新增、保留、剔除和具体原因。
6. 结果区可切换入选、排除、无法判定；点击股票查看逐条件证据；选择两只股票比较。
7. 策略保存到 localStorage；策略版本和 snapshotId 分开记录。

## 架构与模块

### Domain

`src/lib/domain/types.ts` 定义指标白名单、条件、排序、策略、股票记录、证据、筛选结果、Diff、冲突和快照。`src/lib/domain/schema.ts` 用 Zod 校验外部输入。

### 确定性引擎

`src/lib/engine/` 提供冲突检测、单股条件判定、全池筛选、利润同比降序排序和结果 Diff。缺失值返回 `unknown`，不与 `failed` 混同。解释只模板化引用真实值、阈值、单位和日期。

### iFinD 数据适配器

`src/lib/ifind/` 使用 `IFIND_MCP_AUTH_TOKEN` 直接调用 MCP HTTP JSON-RPC，完成 initialize、tools/list、tools/call、超时、内容层错误识别与有限重试。银行股通过两个受控 `search_stocks` 单指标查询获取，严格解析 Markdown 表格，验证 42/42 覆盖、日期列、重复代码、缺失字段和截断提示，再按代码合并。

`src/app/api/bank-snapshot/route.ts` 返回归一化快照和查询证据。实时失败时读取 `data/bank-snapshot.json`，响应中明确 `mode: "historical"` 和错误摘要。

### DeepSeek 意图适配器

`src/lib/ai/` 使用 `DEEPSEEK_API_KEY` 调用 Responses API 严格 JSON Schema。输入包括当前策略以支持局部修改；输出只允许白名单指标，并包括硬条件、软排序、模糊项、澄清项和不支持项。服务端 Zod 二次校验。确定性收益预测或白名单外指标必须进入不支持项并阻止执行。

### Web 工作台

`src/app/page.tsx` 组合聚焦组件：对话输入、策略编辑器、冲突修正、结果标签页、证据详情、Diff、两股比较和保存策略。客户端状态保存当前策略、策略版本、数据快照、筛选结果和上一版本结果；API Key 永不进入客户端。

## 错误处理与可信度

- HTTP 200 但 JSON-RPC content 标记 429/错误时视为失败，按退避策略重试。
- Markdown 为空、截断、列名误映射、日期不符、重复代码、覆盖不一致时拒绝标记实时结果为正常。
- 实时失败可回退历史快照，但必须展示采集时间、指标日期、失败原因和模式。
- DeepSeek 为空、截断、Schema 失败时返回可恢复错误，保留用户原始输入。
- 所有筛选结果带 snapshotId、strategyVersion、数据来源和指标日期。

## 测试策略

- Vitest：Schema、冲突、筛选、排序、Diff、Markdown 解析、429/空/截断/缺失处理、DeepSeek 输出校验。
- React Testing Library：策略编辑、冲突阻止与修正、结果切换、证据详情、Diff、比较、保存恢复。
- Playwright：主链路浏览器验收；真实 API 冒烟单独执行并记录耗时/状态。
- 手动验收：1000 亿得到 16 只，改为 2000 亿得到 12 只，南京银行等 4 只进入剔除 Diff，利润增长降序，两股比较可用。

## 安全与部署

仅服务端读取 `DEEPSEEK_API_KEY`、`IFIND_MCP_AUTH_TOKEN`。提供 `.env.example`，忽略所有 `.env.*`。不记录请求 Authorization，不把原始密钥写入报告、快照或客户端 bundle。Vercel 仅准备配置说明，不作为本轮完成条件。

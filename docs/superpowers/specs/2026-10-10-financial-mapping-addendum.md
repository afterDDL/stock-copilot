# 选股 coPilot 金融语义映射与研究辅助增量规格

## 目的

在现有 P0 主链路上增加可维护的金融语义层，明确区分“理解到什么”“实际能执行什么”和“结果能说明什么”。不得把条件匹配、偏好排序或单指标领先包装为投资价值判断。

## 三层映射

1. 投资者语料层：保存散户、进阶和专业表达及预期动作，用于回归评测。
2. 金融概念/行业层：原始表达映射为投资意图、金融概念和行业适用指标；允许一对多和澄清，不允许概念偷换。
3. 可执行指标层：只有注册表中 `verified: true` 且 `executable: true` 的字段能生成条件。当前仅 `industry`、`market_cap_cny`、`net_profit_parent_yoy_pct`。

四份资产逻辑分离：`concepts.json`、`industry_profiles.json`、`metric_registry.json`、`intent_eval.jsonl`。银行配置完整；其他行业只有示例结构并标为未验证。PB/PE/ROE/波动率等保留候选定义，不可执行。

## Resolver

DeepSeek 输出概念候选、显式数值/方向、硬条件/软偏好、模糊项和局部 patch；本地 Mapping Resolver 使用四份资产决定：

- `confirmed`：明确且已验证可执行；
- `assumed`：有依据的产品预设，可编辑；
- `needs_clarification`：同一表达可映射到不同金融概念且影响结果；
- `unsupported`：概念已理解但没有已验证执行指标。

Resolver 必须保留原始表达、concept、field、解释、单位、时点、默认来源和状态。Unsupported 不得静默删除，只有用户明确缩小范围后才能执行剩余条件。

“盘子大”在银行 P0 使用 1000 亿元产品预设，来源标为产品预设，不声称行业标准；显式数值优先。利润增长越快是排序偏好，不自动增加高于 0% 的硬门槛，除非用户同时表达“仍在增长”。“便宜”“稳”“龙头”“持续改善”“股价低”等必须澄清或不支持，不能偷换成市值/单期利润。

## 数据分布与研究辅助

纯 TypeScript 基于当前 42 股快照计算：样本数、最小/最大/中位总市值、1000 亿元门槛的样本位置、前 30% 门槛、阈值影响数量、每只股票的同业市值排名/分位、距离阈值和边界股票。

研究洞察是代码计算的结构化事实：限制最多的条件、接近阈值股票、因收紧被剔除股票、这些股票仍满足的偏好特征和建议比较对。LLM 如参与只负责改写，不产生名单、排名、数值或投资建议。

结果页分成：

- 条件匹配：通过/排除/无法判定及逐条件证据；
- 偏好排序：明确排序字段、方向和排名依据；
- 研究辅助：同行位置、边界、名单变化和比较线索。

页面必须提示“条件匹配和排序不等于投资价值判断”。

## P0 评测与修改

先实现附件列出的 20 条核心样本，覆盖明确阈值、区间、否定、硬/软条件、澄清、不支持、冲突、局部修改、删除、恢复与收益预测。测试分别报告 concept、condition/preference、direction、mapping、action、conflict/patch 是否符合预期，不以 Schema 通过率代替语义质量。

多轮 patch 至少支持：修改市值下限、删除利润条件、设置利润增长降序、恢复上一策略。模糊“再严格一点”必须澄清。

## 时间与边界

本增量包不得破坏现有真实取数、确定性筛选、Diff、比较和保存。时间不足时优先确保资产/Resolver/20 条评测/映射卡片/样本统计和边界洞察；PB 实取、其他行业执行、完整 50–80 条语料和 LLM 洞察推迟。

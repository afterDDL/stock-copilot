# 选股 coPilot 全 A 股数据能力扩展设计

## 目标与成功标准

把当前仅支持 42 只银行股的本地 MVP 扩展为面向沪深北普通 A 股的真实选股工作台。产品入口、策略模型和结果区不再默认银行；用户可以不指定行业，或指定任一已识别的 iFinD 行业，再使用已验证指标进行确定性筛选。

“支持全 A 股”只有在以下条件同时成立时才允许展示：

- 股票池覆盖沪市、深市和北交所普通 A 股，不混入 B 股、基金、债券、ETF、REIT 或已退市证券；ST 股票保留并按真实名称展示。
- 每个分区都有预期代码集合、实际返回集合、重复数、遗漏数、截断状态和采集时间。
- 合并后的快照能证明代码集合完整；指标缺失可以存在，但必须逐字段统计并归入“无法判定”。
- 筛选、排序、排除原因和 Diff 全部由 TypeScript 引擎基于同一快照执行，LLM 不决定股票入选。

若只能取得部分记录，接口必须返回 `partial`，市场级策略不得执行，界面不得称为“全市场结果”。可继续使用上一份已验证完整的全 A 股快照；现有银行历史快照不能作为全市场降级数据。

## 范围

首轮扩展只改变股票池范围，不同步扩张指标白名单。可执行字段仍为：

- 所属行业；
- 总市值；
- 归属于母公司股东的净利润同比增长率。

行业条件从强制银行改为可选等值条件。没有行业条件表示在完整全 A 股快照中筛选；指定行业时只在该行业分区中筛选。行业名称以 iFinD 返回分类为准，适配层保存原始完整分类并生成可匹配的标准一级行业标签。

本轮不包含 PE、PB、ROE、股息率、行情技术指标、收益预测、交易下单、账户体系或 Vercel 生产部署。银行专用指标不能推广到其他行业。

## 已知约束与设计选择

历史验证表明，一次 `get_stock_financials` 全 A 股查询识别到约 5,572 条记录，但返回内容被截断；当前 MCP 工具没有公开的分页、游标或导出参数。按每五只股票逐批查询两个指标将产生约 2,230 个请求，受频率限制影响，不适合作为交互请求。

因此选择“分区采集、版本化快照、本地筛选”：

1. 用可验证的证券主表确定目标代码全集。
2. 用 iFinD 按稳定分区分别查询单一指标窄表。
3. 对每个分区严格解析和校验，再按股票代码合并。
4. 只有全部分区完成时才发布新的完整快照。
5. Web 请求读取已发布快照并在本地确定性筛选，不在用户等待期间重建全市场数据。

“iFinD 条件选股后仅复核返回候选”不作为完整全市场模式，因为它无法证明未返回列表中没有符合条件的股票。

## 数据采集与覆盖校验

### 证券主表

新增 `UniverseProvider` 接口，输出代码、简称、交易所、上市状态和来源日期。实现优先采用能够证明完整性的沪深北证券名录；若 iFinD 的窄表查询能够完整返回并提供可核对计数，可直接使用 iFinD。否则证券代码主表可来自交易所公开名录，而行业和金融指标仍由 iFinD 提供。

代码统一保存为六位代码，并额外保存交易所后缀。主表生成时拒绝重复代码和无法识别的证券类型。每次刷新记录预期总数和各交易所数量，便于发现异常骤减。

### 分区策略

实现前先运行小型数据探针，验证以下候选分区的返回上限、稳定性和语法：

1. iFinD 一级/二级行业；
2. 交易所加股票代码前缀；
3. 交易所加上市板块。

选择能够做到“分区互斥、并集覆盖主表、单个响应不截断”的最少分区方案。分区清单版本化保存，任何股票落入零个或多个分区都视为覆盖失败。不得依赖 MCP 返回顺序，也不得用 `selectedSecuritiesCount` 代替代码集合核对。

### 指标拉取

每个分区分别执行总市值和归母净利润同比两个受控单指标查询。请求串行或使用低并发队列，默认不超过每秒一次；429 使用指数退避和有限次数重试。每个结果必须验证：

- 无截断提示和内容层错误；
- 代码、名称、行业身份一致；
- 同一查询内没有重复代码；
- 指标列唯一且数值单位可归一化；
- 市值交易日和利润报告期存在且格式有效；
- 返回代码属于目标分区；
- 分区代码与主表预期集合的差异被记录。

指标不存在不等于股票不存在。股票仍进入快照，对应字段标记 `missing`；只有股票记录缺失、意外越界或截断才使分区成为 `partial`。

### 快照发布

采集器先写临时构建目录，生成 manifest 和分区文件，完成全局校验后原子发布为新版本。失败构建不会覆盖上一份完整快照。

本地 MVP 使用版本化 JSON 数据文件，接口通过存储抽象读取；结构预留迁移到 SQLite、对象存储或数据库的能力。manifest 至少包含：

- `snapshotId`、`scope`、`status`、采集开始/完成时间；
- 证券主表日期、总数和各交易所数量；
- 分区版本、每个分区的预期/返回/遗漏/重复/截断状态；
- 每个指标的可用数、缺失数、单位和统计日期分布；
- iFinD 请求数、重试数和错误摘要，不记录认证信息。

## 域模型与 API

`Strategy` 从 `industry: 'bank'` 改为 `market: 'cn_a'`。行业筛选仅通过可选的 `industry` 条件表达；策略可以没有行业条件。

`DataSnapshot` 增加：

- `scope: 'cn_a' | 'industry'`；
- `status: 'complete' | 'partial'`；
- 交易所覆盖和分区覆盖；
- 各指标的统计日期分布，而不是写死单一银行日期。

股票记录保存标准行业与 iFinD 原始行业路径。行业比较采用标准标签精确匹配，不使用任意字符串包含；同义词在意图层解析为标准标签。

新增通用 `/api/stock-snapshot`，支持读取当前完整全市场快照，也可以按行业裁剪响应。旧 `/api/bank-snapshot` 在迁移期只供回归测试，前端不再调用。接口返回 `complete` 快照才能执行；若刷新失败且存在上一份完整快照，则返回旧快照并明确陈旧状态。若没有完整快照，返回可恢复错误，不回退银行样本。

前端结果列表必须分页或虚拟化，避免一次渲染数千条排除记录。比较、证据、Diff 和保存策略继续复用现有模块。

## LLM 与映射层

DeepSeek 仍只负责意图解析。系统提示和 Schema 的变化为：

- 默认市场范围为全 A 股，不自动插入银行条件；
- 用户明确说“银行、半导体、白酒”等行业时生成行业条件；
- 行业表达必须经过本地行业词典解析，无法唯一映射时澄清；
- 用户未指定行业时不澄清，直接表示全市场；
- 未验证指标继续进入 `unsupported_requests`；
- 当前策略局部修改可新增、替换或删除行业条件。

Mapping Registry 将指标适用范围从 `bank` 调整为 `cn_a`，但只有完成跨行业样本校验的字段才能标记 `verified`。银行专用候选指标继续保持行业限定。

## 用户界面

界面整体保持现有 ChatGPT 式研究工作台，产品定位改成全市场：

- 欢迎区和输入示例使用跨行业表达，不再出现银行限定；
- 当前策略显示“全 A 股”或已选行业；
- 结果区展示沪/深/北数量、快照日期、完整/陈旧状态和指标缺失数；
- 全市场结果默认只渲染当前标签页的分页数据；
- `partial` 快照显示阻断卡片，说明缺失分区且禁用“运行筛选”；
- 历史银行快照只出现在开发诊断或回归测试中，不出现在正常用户流程。

界面可以呈现全市场产品形态，但只有完整快照发布后才使用“全 A 股结果”等承诺性文案。

用户界面采用渐进披露，不堆叠防御性声明。正常流程只显示完成当前操作所需的信息：需要用户补充时直接询问缺少的条件；请求尚未接入时只说明“暂不支持该指标查询”。内部字段名、分区术语、Schema 名称、MCP 错误分类和长篇完整性说明不进入主要界面。数据日期、来源、覆盖状态和缺失数量保留为简洁摘要，详细诊断收纳在可展开的数据状态详情和开发日志中。

## 错误处理与安全

- 认证信息仅从服务端环境变量读取，不进入日志、快照或客户端。
- 采集错误按网络、授权、频率限制、内容截断、列映射、日期、身份和覆盖失败分类。
- 429 退避有最大次数；到达上限后保留上一完整快照并结束刷新，不无限重试。
- 市场范围或行业分区覆盖无法证明时，宁可阻止执行，也不返回貌似正常的候选列表。
- 快照 manifest 和 UI 均明确区分证券池完整性与单个指标覆盖率。

## 迁移顺序

1. 建立只读数据探针，验证证券主表与稳定分区策略；记录实测返回数量、截断、耗时和限流。
2. 泛化领域 Schema、筛选引擎和意图解析，移除强制银行条件。
3. 实现分区采集器、覆盖校验、版本化快照和 `/api/stock-snapshot`。
4. 生成并验证首份真实全 A 股快照；未完成前不切换产品承诺。
5. 修改前端文案、范围状态、分页和数据质量展示。
6. 更新映射资产、自动化测试、文档和端到端验收。

## 测试与验收

### 自动化测试

- Schema：全市场策略、可选行业、未知行业、完整/部分快照和多日期分布。
- 采集器：分区合并、重复、遗漏、越界代码、截断、空结果、单位、日期和内容层 429。
- 引擎：无行业条件、跨行业筛选、行业筛选、缺失指标、排序和 Diff。
- Intent：默认全市场、指定行业、删除/更换行业、未支持指标和局部修改。
- API：完整快照、旧完整快照降级、无完整快照、行业裁剪及不泄露上游错误内容。
- UI：全市场文案、覆盖阻断、分页、证据、比较和策略保存。

### 真实数据验收

- 证券主表数量与各交易所数量有来源和日期，代码集合无重复。
- 所有分区的并集与主表一致，交集为空；每个响应无截断。
- 总市值和利润同比分别报告可用/缺失数量与日期分布。
- 不带行业条件的策略能在完整全市场快照运行；指定至少两个非银行行业能得到真实结果。
- 同一快照上修改阈值可重复执行并产生可解释 Diff。
- MCP 429、超时或某分区失败时不会发布部分快照。
- 银行基准用例仍可从全市场快照裁剪复现，作为回归而非产品默认范围。

## 完成定义与阻塞条件

只有首份真实、完整、可重复生成的全 A 股快照通过上述覆盖校验，前端才算完成全市场切换。若 iFinD 的自然语言查询无法形成稳定且完整的分区，任务进入数据源阻塞：保留已完成的通用领域/UI 改造，但不得声称真实全 A 股已上线；下一选择是接入可分页的证券/指标数据接口，而不是降低完整性标准。
